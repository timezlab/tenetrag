Method [paper]:
- Offline: LightRAG-style LLM triple extraction. Each entity gets one *contextual attribute description per chunk occurrence* (NOT merged into one summary); each encoded as f(name || attribute) -> N attribute embeddings per entity. Chunk links kept (HippoRAG2-style).
- Canonicalization: cross-synonym ("cousin") edge between e_i, e_j if ANY pair of attribute embeddings has cosine > tau; cross-language pairs = cross-synonym. Nodes are not merged, linked.
- Custom embedding: 2-stage fine-tune (SimCSE on synthetic VI/EN attribute descriptions; supervised contrastive with hard negatives on 5 bilingual query-desc pair types).
- Online: query embedding -> top-k over attribute embeddings + edge-description embeddings = seeds -> their chunks (C_init); expand via cousin nodes, take chunk of best-matching attribute (C_cousin); rank by composite = w_chunk*norm(chunk sim) + w_attr*norm(avg top-m attr sim, boosted by max over cousins) + w_triple*norm(avg top-m triple sim). Top-n chunks to LLM.

Ablation (Table 2, vi-en R@10 NQ/PopQA/MuSiQue): LightRAG 23.11/23.32/20.30 -> +granular retrieval 78.90/49.10/48.86 -> +cross-synonym 80.73/49.20/51.21 -> +composite score 88.58/50.08/56.96 -> +finetune 87.79/50.65/60.37.
Composite ablation (Table 4): w/o s_chunk 73.91/47.55/49.91 (largest drop); w/o s_attr 87.37/49.70/58.34; w/o s_triple 85.69/48.50/57.12.
Caveats: datasets machine-translated with Gemini 2.0 Flash to create cross-lingual pairs; QA quality = win rates judged by Grok-3 (LLM judge); Wikipedia/legal QA, not enterprise; no code; all GRAG baselines with Gemini 2.0 Flash + BGE-M3.
Takeaways: (1) per-chunk contextual descriptions instead of merged summaries is the dominant gain; (2) chunk similarity is the most important ranking signal; (3) dense BGE-M3 beats GraphRAG-Local/LightRAG by large margins on retrieval recall — graph engines' merged-description retrieval underperforms; (4) cross-lingual ER via contextual (name+context) embeddings, linking not merging; (5) fine-tuning adds little.
