## Summary (10 lines)
1. llama-index-core 0.14.25 (2026-09-21), MIT, Python >=3.10,<4, Pydantic >=2.8, 25 hard deps including nltk, sqlalchemy[asyncio], networkx, numpy, pillow, tiktoken, aiohttp, requests, fsspec. [pypi]
2. `import llama_index.core` eagerly imports sqlalchemy and Pillow (top-level `__init__` pulls indices, SQLDatabase, schema). Not light. [source]
3. Ambient credentials: `Settings.llm` / `Settings.embed_model` default to OpenAI and read OPENAI_API_KEY on first access; many components do `llm or Settings.llm`. `Databricks` LLM/embedding classes read DATABRICKS_TOKEN, and the LLM class then falls through to OPENAI_API_KEY / api.openai.com. Violates ADR 0003 unless fully wrapped. [source]
4. No telemetry in core (grep clean). NLTK and tiktoken data are bundled in the wheel, so no network in the default path, unless NLTK_DATA is set. [source]
5. Chunking: offsets are recovered by `str.find` after the fact, node ids are `uuid4` unless an `id_func` is passed, chunks are `.strip()`ed, and the default tokenizer is tiktoken gpt-3.5. Usable only with our own offset verification; semchunk gives exact offsets by construction with 1 dep (tqdm). [source]
6. Query transforms and fusion are tiny (HyDE ~25 lines, RRF ~25 lines, multi-query ~10); `StepDecomposeQueryTransform` says "NOTE: doesn't work yet." Port, do not depend. [source]
7. IngestionPipeline/docstore hashing (metadata-inclusive node hash, SimpleDocumentStore) conflicts with our two-level hashing and run model; PropertyGraph extractors build Pydantic `Literal` triplets with no dates/evidence/facts and bypass our pack compiler. Do not use. [source]
8. Cadence: 20 core releases in the last 12 months (0.14.5 to 0.14.25), all within 0.14.x, with small breaking changes (e.g. `metadata_seperator` field removed from TextNode in 0.14.15). Integrations pin `llama-index-core<0.15`. [pypi][source]
9. Best reuse is not LlamaIndex: pypdf/python-docx/python-pptx/openpyxl directly (or markitdown/docling in extras), semchunk for splitting, bm25s for sparse, sentence-transformers CrossEncoder for reranking, MLflow's RAGAS/DeepEval scorers for eval.
10. Proposed ADR 0001 wording at the end (section 6).

## 2. Side effects (fail-closed credentials, light import)
All paths at `llama-index-core/llama_index/core/` @ v0.14.25 unless noted.
- **Default OpenAI** [source]: `settings.py:37-38` `if self._llm is None: self._llm = resolve_llm("default")`; `settings.py:66` same for `resolve_embed_model("default")`. `llms/utils.py:50-57` builds `OpenAI()` and calls `validate_openai_api_key(llm.api_key)`; `embeddings/utils.py:49-58` same for embeddings. The key comes from `resolve_openai_credentials` (`llama-index-llms-openai/.../utils.py:1043`: param, then `OPENAI_API_KEY`, then `openai.api_key` module global). It fails with ValueError if absent (not AuthError) and silently uses the ambient key if present. `IS_TESTING` env returns MockLLM (`llms/utils.py:41-46`).
- **Implicit `Settings` fallbacks in components** [source]: `HyDEQueryTransform` (`indices/query/query_transform/base.py:126`), `StepDecomposeQueryTransform` (`:282`), `QueryFusionRetriever` (`retrievers/fusion_retriever.py:63`), `LLMRerank` (`postprocessor/llm_rerank.py:50`), `FaithfulnessEvaluator` (`evaluation/faithfulness.py:125`), `DynamicLLMPathExtractor`/`SimpleLLMPathExtractor`/`SchemaLLMPathExtractor` (`dynamic_llm.py:271`, `simple_llm.py:79`), `PptxReader` (`readers/file/slides/base.py:62-63`, only with `context_consolidation_with_llm=True`), `SemanticSplitterNodeParser` constructs `OpenAIEmbedding()` when `embed_model is None` (`node_parser/text/semantic_splitter.py:99-105`). Passing an explicit instance avoids each, but nothing forces it.
- **Databricks classes read env and then fall into OpenAI env** [source, tag]: `llms/llama-index-llms-databricks/.../base.py:36-37` `api_key = api_key or os.environ.get("DATABRICKS_TOKEN")`, `api_base = api_base or os.environ.get("DATABRICKS_SERVING_ENDPOINT")`; both are passed to `OpenAILike` then `OpenAI.__init__`, which runs `resolve_openai_credentials` (`llama-index-llms-openai/.../base.py:300`). ## 3. Per-step standalone usability
### 3a. Readers (llama-index-readers-file 0.7.0)
- PDF: `PDFReader` (`readers/file/docs/base.py:28-98`) uses `pypdf` (BSD-3-Clause [pypi]); one Document per page with `{"page_label", "file_name"}` (`:94`), or whole-file when `return_full_document=True` (`:83`). Page text only; no character offsets, no layout/tables/OCR. `PyMuPDFReader` exists (`pymu_pdf/base.py:44` `import fitz`) behind the `pymupdf` extra: AGPL-3.0 or commercial [pypi: pymupdf 1.28.2]. Exclude.
- DOCX: `DocxReader` (`docs/base.py:103-133`) uses `docx2txt` (lazy; no license metadata on PyPI [pypi]); returns one Document, only `file_name` metadata, no headings/tables structure.
- PPTX: `PptxReader` (`slides/base.py`) one Document per slide with rich metadata (title, tables, charts, notes). Uses python-pptx (MIT [pypi]); optional LLM/image captioning falls back to `Settings.llm` (`:62-63`).
- XLSX: `PandasExcelReader` (`tabular/base.py:136-256`) via pandas+openpyxl (MIT); rows joined as text, metadata is just `extra_info`; sheet name is not recorded in Document metadata in the lines read (`:222-256`) [source, partial read].
- Markdown: `MarkdownReader` (`markdown/base.py`) splits on headers, strips images/links, metadata only `extra_info`. Note `MarkdownReader` modifies text (remove_images/remove_hyperlinks, `:103-113`), so offsets back into the source file would not hold [source].
- All readers return LlamaIndex `Document` (Pydantic, uuid4 id by default), loaded from a path/fsspec handle. They need no index. [inferred: usable standalone, one-liner `Reader().load_data(Path)`]. `SimpleDirectoryReader` defaults `errors="ignore"` (`readers/file/base.py:256`), which is a silent-skip posture at odds with our "never swallow" rule.
- Verdict [inferred]: the readers are thin wrappers over pypdf/python-docx/python-pptx/openpyxl that add LlamaIndex Document/pandas coupling and lose structure. Calling those libraries directly (all permissive) is less code than wrapping.

### 3b. Node parsers / splitters
- Offsets [source]: `node_parser/interface.py:100-118` `_postprocess_parsed_nodes`: `start_char_idx = parent_doc.text.find(node_content, search_start)`; set only `if start_char_idx >= 0`; `end_char_idx = start + len(node_content)`; next search starts at `start+1`. So offsets are a post-hoc string search, not tracked during splitting. Failures leave them `None`; repeated identical text could map to the wrong occurrence (search proceeds monotonically from the previous start, which mitigates but does not prove correctness) [inferred].
- Whitespace: `SentenceSplitter._postprocess_chunks` strips each chunk (`node_parser/text/sentence.py:325-328`); so the chunk text is a stripped substring, and `find` still works on substring equality. Chunks that came from joined splits with internal modifications would not match [inferred].
- IDs: `node_parser/node_utils.py:25-26` `default_id_func` returns `str(uuid.uuid4())`; `schema.py:276` BaseNode id default is uuid4. Deterministic only if you pass `id_func` [source].
- Determinism: splitting logic is pure given a fixed tokenizer; non-determinism comes from ids. `SemanticSplitterNodeParser` depends on embeddings (needs an `embed_model`, else builds OpenAI one, `semantic_splitter.py:99-105`); `SemanticDoubleMergingSplitterNodeParser` needs NLTK stopwords (`:58`), English only. [source]
- Tokenizer: default `get_tokenizer()` = tiktoken gpt-3.5 (`sentence.py:104`); can pass any `tokenizer=callable`. Sentence splitting uses `PunktSentenceTokenizer()` constructed with no training data (`utils.py:115,129`), which is language-agnostic punctuation-based; Vietnamese works at the level of ". ! ?" boundaries, with English abbreviation heuristics absent [inferred]. cl100k on Vietnamese yields many more tokens per word than English [inferred; not measured]. No NFC normalization anywhere in the splitters [inferred from grep not finding it; not exhaustively searched].
- `MarkdownNodeParser` (`node_parser/file/markdown.py`): header-split with `header_path` metadata, code-fence aware; it calls `.strip()` on sections (`:67-78`); relies on the same `find`-based offsets. `HierarchicalNodeParser` (`relational/hierarchical.py`) only composes splitters into parent/child nodes.
- `include_metadata=True` merges parent doc metadata into each node (`interface.py:121-123`) and metadata-aware splitting shrinks chunk size by metadata token length (`sentence.py:156-157`): chunk boundaries then depend on metadata, a hidden coupling to our hashing [source].
- Verdict [inferred]: workable behind our own offset assertion (`text[start:end] == chunk`), but you inherit Settings/uuid/metadata coupling. `semchunk` (below) provides exact offsets natively.

### 3c. LLM and embedding integrations
- All three (Databricks, OpenAI-like, Anthropic) are Pydantic LlamaIndex `LLM` classes whose value is message translation, retries, streaming, tool-call mapping, and `structured_predict`.
- Credentials: see section 2: env fallbacks in Databricks (LLM and embeddings), OpenAI(-like) and Anthropic SDK; one static token, no refresh/OAuth/OBO hook. A wrapper could pass explicit `api_key`/`api_base` and a custom `http_client`; the OpenAI-like classes accept `http_client`/`async_http_client` (docstring in `openai_like/base.py`) so a per-request auth header could be injected [inferred]. Even then `OPENAI_API_BASE` env can still redirect when `api_base` is omitted, so every parameter must be explicit.
- Structured output: OpenAI path uses `response_format = _type_to_response_format(output_cls)` from the `openai` SDK (`llama-index-llms-openai/.../base.py:1109-1120`), which takes a Pydantic class, not a raw JSON Schema dict. Anthropic path calls `client.beta.messages.parse(..., output_format=output_cls, betas=["structured-outputs-2025-11-13"])` (`llama-index-llms-anthropic/.../base.py:1095-1100`) with a Pydantic class, and falls back to the generic tool-calling program on Bedrock/Vertex or unsupported models (`:1087-1092`). Our packs compile to flat JSON Schema dicts (no `$ref`/`anyOf`, <=64 keys), so we would have to build Pydantic classes from them (`create_model`) and trust the SDKs' own schema transformation, or bypass `structured_predict` and pass raw kwargs [inferred]. Databricks-specific: the Databricks class only special-cases `tool_choice` (`databricks/base.py:44-50`); its JSON-schema behavior is the OpenAI-like one [source].
- Versus our own thin clients: what we need is `chat(messages, response_schema) -> text/json` plus capability profiles, which ADR (architecture `llm` module) already plans as one class per provider over the official SDKs (`openai`, `anthropic`, `databricks-sdk`). The LlamaIndex layer would sit between our protocol and those SDKs and add Settings, callback/instrumentation, Pydantic-program-mode semantics and its own retry. [inferred: write our own; the official SDK is the correct reuse boundary].

### 3d. Query transforms and fusion
- `HyDEQueryTransform` (`query_transform/base.py:96-150`): one `llm.predict(prompt, context_str=query)` call; returns a `QueryBundle` with `custom_embedding_strs`. About 25 lines of logic; the prompt is `DEFAULT_HYDE_PROMPT` (English, in `prompts/default_prompts.py`). Needs LlamaIndex `LLM` and `QueryBundle`. Falls back to `Settings.llm` (`:126`). [source]
- `StepDecomposeQueryTransform` (`:259-321`): docstring literally says "NOTE: doesn't work yet." (`:266`). Do not use. [source]
- `QueryFusionRetriever` (`retrievers/fusion_retriever.py`, 317 lines): takes a `List[BaseRetriever]`, so our retrievers must be wrapped in LlamaIndex `BaseRetriever` returning `NodeWithScore`; query generation = one `llm.complete(prompt)` split by newline (`:80-100`); RRF with k=60 (`:122-141`). Fusion key is `node.hash` (`:131`), which is a hash of text+metadata (`schema.py:742-762`), not our chunk id: two chunks with identical text/metadata collapse, and different metadata splits one chunk in two. Modes: reciprocal_rerank, relative_score, dist_based_score, simple. [source]
- Port cost [inferred]: RRF = about 12 lines (`score[id] += 1/(k+rank)`), multi-query generation = about 10 lines plus our own prompt (needs Vietnamese-aware, no-translation wording anyway), HyDE = about 8 lines. Porting with attribution comments (ADR 0001 existing practice) is simpler than the `BaseRetriever`/`QueryBundle`/`Settings` surface. Our retriever callables are plain functions, so a thin `rrf(rankings: list[list[ChunkId]], k=60)` keyed by our ids is the right unit.

### 3e. Rerankers / postprocessors
- `SentenceTransformerRerank` is in core (`postprocessor/sbert_rerank.py`): lazily imports `sentence_transformers.CrossEncoder` (`:38-51`), `device` auto-inferred, and **`__init__` default `trust_remote_code=True`** (`:35`; the Field default is False at `:24`, but the constructor default wins) so a Hugging Face model with custom code would execute remote code [source]. Default model `cross-encoder/stsb-distilroberta-base` (a similarity model, not a retrieval reranker) (`:32`). Input/outputs are `NodeWithScore`. Model download happens in `CrossEncoder(...)` from the Hub [inferred].
- `FlagEmbeddingReranker` (separate package): thin wrapper around `FlagEmbedding.FlagReranker(model, use_fp16)` (`flag_embedding_reranker/base.py:27-39`). FlagEmbedding 1.4.2 is MIT [GitHub license API] but requires torch, transformers, datasets, accelerate, sentence_transformers, peft, ir-datasets, sentencepiece, protobuf [pypi]: very heavy.
- `LLMRerank` (`llm_rerank.py`): prompt-based, parses choice lines, `Settings.llm` fallback (`:50`). `StructuredLLMRerank` got native async in 0.14.25 (changelog).
- Verdict [inferred]: for cross-encoders, call `sentence_transformers.CrossEncoder` directly (Apache-2.0 [pypi]) with `trust_remote_code=False`; the wrapper saves about 15 lines and adds the unsafe default.

### 3f. IngestionPipeline + docstore dedupe/caching
- `IngestionPipeline` (`ingestion/pipeline.py`, 882 lines): `DocstoreStrategy` UPSERTS / DUPLICATES_ONLY / UPSERTS_AND_DELETE (`:242-251`); dedupe uses `node.hash` and `ref_doc_id` stored in a `SimpleDocumentStore` (in-memory with JSON persist; `:410-421`, `:455-531`). Transformation cache key = sha256 of `get_content(MetadataMode.ALL)` of all input nodes plus the transformation dict (`:58-69`).
- `TextNode.hash` = sha256 over metadata string (MetadataMode.ALL) + text resource hash (`schema.py:742-762`): the document hash is not a raw-bytes/NFC-text hash, and changing any metadata key (including `file_name` or `page_label`) changes the hash.
- Default transformations are `[SentenceSplitter(), Settings.embed_model]` (`:424-427`) so omitted arguments trigger the OpenAI default.
- It also owns run structure: upserts call `vector_store.delete(ref_doc_id)` (`:488,505`) and batch via a `spawn` multiprocessing pool (`:606-616`); it has no concept of our index run, transactions, one-writer rule, graph/fact cascade deletes, or Delta/Postgres batching. [source; conflict conclusion is inferred]
- Verdict [inferred]: do not use. The useful ideas (cache keyed by input hash + transformation config) are reimplemented against our hash columns in about 30 lines.

### 3g. PropertyGraphIndex extractors
- `SchemaLLMPathExtractor` (`indices/property_graph/transformations/schema_llm.py`): builds a Pydantic model at runtime with `create_model("Triplet", subject=(entity_cls,...), relation=(relation_cls,...), object=(entity_cls,...))` and `KGSchema(triplets=List[Triplet])` (`:200-233`), with `Literal` types for entity and relation names; validation drops non-conforming triplets (`:262-340`, `strict`). Output is (subject, relation, object) triples with optional string props; no event/fact/date/evidence-span objects, no per-field cardinality, no pack provenance. The nested model emits `$defs`/`$ref` in its JSON Schema when passed to providers [inferred; not executed], conflicting with our flat-schema rule. `DynamicLLMPathExtractor`/`SimpleLLMPathExtractor` are free-form text parsing with `Settings.llm` fallback.
- Verdict [inferred]: conflicts with the domain-pack compiler and validator (our schema, ADR 0007). Keep as a prompt/algorithm reference only (already in graphrag-engines.md).

### 3h. Evaluation
- LlamaIndex `evaluation/` has LLM-judge evaluators (faithfulness, relevancy, correctness, answer_relevancy, context_relevancy, pairwise, guideline) plus retrieval metrics and dataset generation; each takes an LLM or falls back to `Settings.llm` (e.g. `faithfulness.py:125`) [source]. They operate on `Response`/`NodeWithScore`-shaped inputs.
- MLflow GenAI docs list third-party scorer integrations for DeepEval, RAGAS, Arize Phoenix, TruLens, Guardrails AI, Google ADK [docs: mlflow.org/docs/latest/genai/eval-monitor/scorers/third-party/]; import paths and versions not shown on the index page (not verified further).
- Verdict [inferred]: since ADR 0004/architecture say `benchmark` logs MLflow runs, use MLflow scorers with RAGAS/DeepEval in the `bench` extra and keep our own retrieval metrics (recall@k by chunk id/provenance); LlamaIndex evaluators add a second LLM-judge stack with the Settings coupling and no MLflow link.

## 4. Release cadence and breaking changes (llama-index-core 0.14.x)
- PyPI shows 20 releases between 2025-10-04 and 2026-10-04: 0.14.5 (2025-10-15) ... 0.14.25 (2026-09-21), roughly 1.7/month; the gap grows lately (0.14.22 2026-05-14, 0.14.23 2026-06-24, 0.14.24 2026-08-19, 0.14.25 2026-09-21) [pypi]. No 0.15 yet; every modular package pins `core<0.15`.
- From `CHANGELOG.md` @ v0.14.25, core entries that touch API: 0.14.25 "Remove deprecated ipex-llm and optimum-intel IPEX integrations (#22406)"; 0.14.22 "remove stale exports from public `__all__` lists (#21133)"; 0.14.18/17 "deprecate python 3.9 once and for all (#20956)"; 0.14.16 "deprecate asyncio_module in favour of get_asyncio_module (#20902)"; 0.14.15 "remove redundant `metadata_seperator` field from TextNode (#20649)" (a serialized-schema change); 0.14.24 "use word tokenization for stopword removal in SemanticDoubleMergingSplitterNodeParser (#22167)" (behavioral change in a splitter, i.e. chunk boundaries can change between patch releases). 0.14.25 also carries "fix: resolve a ton of security alerts (#22855)" across ~all integrations (a mass version bump on 2026-09-21) [source].
- Implication [inferred]: patch releases have changed splitter behavior and Node schema; for deterministic chunking and stable hashes any LlamaIndex splitter would need an exact pin and a golden-chunk regression test. This echoes the ADR 0001 point about tracking upstream.

## 6. Recommendation [inferred] and proposed ADR 0001 wording
| Step | Reuse candidate | How to wrap | Risks |
|---|---|---|---|
| PDF parse | `pypdf` (BSD-3) direct; optional `docling` for scans/layout | parser registry in `ingest`; extra `parse-pdf` / `docling` | pypdf text quality and no OCR; docling torch size and first-use model download (prefetch + `artifacts_path`); never PyMuPDF (AGPL) |
| DOCX/PPTX/XLSX | python-docx, python-pptx, openpyxl direct (MIT); or `markitdown[docx,pptx,xlsx]` | one parser class per format, returning our `ParsedDocument` (text + page/slide/sheet spans) | LlamaIndex readers drop structure; markitdown rewrites text so offsets refer to converted Markdown, which must be stored as the canonical text |
| Markdown | own heading-aware splitter (small) | `engine`/`ingest` own code | none |
| Chunking | `semchunk` (MIT, tqdm only) with our own token counter and NFC-normalized input; write our own wrapper that stores `(start,end)` and asserts `text[start:end]==chunk` | `ingest.chunking` adapter; extra not needed (1 light dep), or `chunk` extra | Splitting is generic; golden-test determinism; Vietnamese token counter choice. LlamaIndex splitters: only with `id_func`, own `tokenizer`, offset assertion, exact version pin. |
| Chunk/doc hashing, incremental index | write our own | `ingest`, stdlib hashlib | LlamaIndex pipeline conflicts (metadata-inclusive hash, own docstore) |
| LLM / embedding clients | write our own thin classes over official SDKs (`openai`, `anthropic`, `databricks-sdk`) | `llm` module, explicit credentials, extras `openai`, `anthropic`, `databricks` | LlamaIndex classes read env (section 2), take Pydantic classes for structured output, static tokens only |
| Query transforms (HyDE, multi-query, step decompose) | write our own (about 10-25 lines each), cite LlamaIndex file/tag in attribution comment | `engine` with `ChatModel` protocol | Prompts must be Vietnamese-safe, no translation of source |
| Fusion (RRF) | write our own | `engine` pure function keyed by chunk id | LlamaIndex fuses on `node.hash` |
| Rerank | `sentence_transformers.CrossEncoder` direct; LLM rerank own prompt | `RerankerModel` adapter in `llm` (or `retrieval` adapter), extra `rerank` | `trust_remote_code=False`; model licenses (avoid CC BY-NC jina rerankers per supporting-libraries.md); torch weight |
| Sparse retrieval | Postgres FTS / AI Search first; `bm25s` for in-memory/tests | adapter behind `VectorStore`/sparse protocol, extra `bm25` | English stopword default and `\w\w+` tokenizer; set stopwords=None |
| Schema extraction | write our own (pack compiler + validator) | n/a | LlamaIndex extractors produce triples, not dated evidenced facts |
| Evaluation | MLflow scorers + RAGAS/DeepEval | `benchmark` extra `bench` | LLM-judge prompts are English; judge cost; verify import paths in installed version |
| Optional bridge | `llama-index-core` only as an adapter *for users* (e.g. exposing our retriever as a LlamaIndex `BaseRetriever`) | separate extra `llamaindex`, outside `engine`, never default | import weight, Settings global, 0.14.x churn |

Proposed amended rule for ADR 0001 ("Must now be true"), replacing the first bullet:
> Third-party libraries, including `llama-index-*`, may be used outside `engine` (in `ingest`, `llm`, `storage`, `benchmark`) only behind an adapter that implements one of our protocols or registries, and only when all of the following hold: (1) the license is permissive (MIT, BSD, Apache-2.0, or equivalent; no GPL or AGPL, even optional); (2) it sits in an optional extra and importing the base package does not import it; (3) it reads no ambient credentials: every key, token, endpoint and base URL is passed explicitly by our adapter, and a missing one raises `AuthError` rather than falling back to environment variables, module globals (e.g. `Settings`, `openai.api_key`) or another identity; (4) it sends no telemetry and performs no network or model download at import or first use unless the adapter exposes it as an explicit, documented, disable-able step; (5) it does not own chunk ids, offsets, hashes, run or transaction state, or the graph schema: the adapter must verify `text[start:end] == chunk` and produce our deterministic ids and hashes; (6) its version is pinned and covered by a golden test where its output feeds hashing or chunking. `graphrag` and `lightrag-hku` remain architecture references only and are never imported.
Suggested "Revisit if" addition: reconsider `llama-index-*` as a first-class dependency if core drops its eager sqlalchemy/Pillow imports and its `Settings` defaults become opt-in.

- Docs state "Docling model-weight licenses: unverified" in supporting-libraries.md; HF API shows apache-2.0 / cdla-permissive-2.0 for two repos, but other models (OCR, VLM) were not checked.
